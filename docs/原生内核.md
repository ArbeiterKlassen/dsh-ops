# 原生内核工作区

English: [native-kernel.md](native-kernel.md).

`dsh-ops-worker` 仍然是唯一的可执行文件。每次调用都经过 DSH 的 subprocess 和权限沙箱，
重新核实权限，读取一次有大小上限的 JSON 请求，再输出一个 JSON 结果。拆分内核不会引入常驻进程。

| crate | 职责 | 内核依赖 |
| --- | --- | --- |
| `ops-protocol` | 请求、错误、作业记录、凭据路径和归属校验 | 无 |
| `ops-files` | 禁止跟随链接的句柄、读取、CAS 发布、元数据、树操作、目录同步 | protocol |
| `ops-search` | 基于受保护文件原语的 glob、grep 和替换编排 | protocol、files |
| `ops-results` | 有界的代际存储、结果分页和只读作业审计访问 | protocol、files |
| `ops-batch` | 计划、预写状态转移和保守恢复 | protocol、files、results |

根 crate 负责分派请求，仅为 batch/result 能力打开审计存储。作业归属校验与协议记录放在一起，
避免结果模块依赖批处理执行模块。Windows 和 Darwin 元数据 crate 仍是独立 FFI 边界；内核 crate
禁止 unsafe Rust。替换操作保留观察锁直到发布完成；批处理在产生文件系统副作用前持久化 unknown
状态。只读文件调用不会创建审计存储。

使用 `cargo test --workspace --locked --manifest-path native/Cargo.toml`，确保迁入各 crate 的
测试全部执行。`npm run build:ptc` 的 worker 输出路径保持不变。发布包包含 `native/crates/`
及两个元数据适配器，支持安装后的源码构建。基准测试预检检查整个工作区的构建输入，并排除 Cargo
的 target 目录。

## 单次请求协议

新的宿主桥接发送 `{ version: 1, requestId, component, budget, request }`。`request` 保留严格的
能力参数和宿主权限字段；`component` 为 `file` 或 `ptc`，不会授予权限。桥接生成新的 UUID，
填入真实会话、根路径和策略，并在启动进程前再次核实权限。普通成功字段保留原有语义；可选引用字段见下文。

`budget.timeoutMs` 范围为 1..2147483647 毫秒，沿用现有 300000 毫秒默认值及宿主取消机制。
进程内的看门狗也会约束直接调用；超时退出码为 124，桥接将副作用报告为 unknown。
`budget.maxBytes` 范围为 1024..131072，默认 131072，计算序列化 JSON 与末尾换行的总字节数。
下限保证结构化错误有足够空间。没有可信存储的读取输出超限返回 `OUTPUT_LIMIT` 且无副作用；修改回执丢失则
报告 unknown，除非已有错误携带更精确的副作用状态。不会自动重试。

完整请求仍以 2 MiB 为上限。为兼容 0.3.x 基准对比，显式保留旧版无版本请求，采用相同权限检查和
有界默认传输预算。只要出现任一信封字段，就严格按 v1 解析；缺字段、未知字段、非法 ID、
不支持的组件或版本、无法使用的预算，均在文件系统副作用前被拒绝。请求 ID 不改变结果哈希。
自动输出溢出见下文。

## 会话快照引用（6a/16）

worker 接受可选的可信信封元数据 `storage: { root, authorityId, allowedTools, windowsWriteSid? }`。
工具参数和内层 request 均不能注入这些字段。宿主提供已存在的绝对缓存根目录、64 位小写 SHA-256
权限身份，以及当前规范化生产工具白名单。权限身份必须绑定本次会话随机标识、当前策略和凭据
边界；知道引用不等于获得权限。每次访问仍核实会话、选定的规范化根路径及目录身份、生产工具和
当前凭据边界。可信缓存根目录是独立的缓存专用授权，不随操作根目录选择而改变，也不受业务 write_roots 限制；
绝不将缓存位置加入业务修改白名单。

带此上下文的 result put 返回 `ref://<编码会话>/<工具>/<uuid>`，并提供 `reference` 元数据：
refId、createdAt（Unix 毫秒）、ttlMs、schemaVersion、producerTool、totalItems、totalBytes
（实际序列化快照字节数），以及最多十行、512 字符的预览。默认 `ttlMs: 0` 表示会话生命周期；
显式正数 TTL 最多七天。宿主须在会话结束时使引用失效，重新打开会话时更新权限身份。单个快照
最多 10 MiB，每会话缓存最多 100 MiB/4096 项；崩溃暂存和未知文件也计入配额。写入者通过同一
进程间锁串行作出配额/LRU 决策。只淘汰规范 UUID 快照名；不可变审计记录永不参与 LRU。

分页返回 sourceTotal、筛选后的 total、items、nextOffset、omitted、complete；complete 仅表示
选定的已存储行全部展示，不意味着原始业务扫描完整。512..65536 字节分页预算计入 JSON 转义、
引用元数据和末尾换行。单行过大时必须选择更少字段或增大页预算；引用分页不会生成另一层引用。
拒绝嵌套引用对象，普通字符串中的 URI 仍是普通数据。只读分页仅打开已有共享锁，不创建文件、
不更新 LRU 时间。丢失、过期、释放或淘汰的快照返回 `REFERENCE_EXPIRED`。旧 r-/j- 访问保持
原有协议和持久审计位置。

Windows 宿主提供受限调用实际的私有 `--temp` 和 `--temp-write-sid`，并为只读访问保留该位置。
受保护缓存 DACL 仅授予当前用户及这个私有临时能力，且该能力必须已存在于持有的父目录句柄上。
拒绝公共组、登录组和工作区能力 SID。真实只读及其他会话令牌无法写入这些对象。POSIX 文件和
目录归当前用户所有且权限私有。缓存父目录、子目录、快照和稳定锁均拒绝链接或 reparse point；
文件只允许单一硬链接。缓存操作不会修改业务文件权限。

宿主生命周期清理使用相同可信上下文发送 `result { action: "purge" }`，不接受其他参数。仅删除
该会话范围内已验证的快照/暂存名，保留锁 inode、目录以及未知/审计名称。结果包含 removed、
retained、complete、effectState；部分清理失败会明确已有副作用。只读模式拒绝 purge。宿主必须
先在逻辑上使引用失效，再等待活动调用结束；清理被拒绝或中断时延后清理，绝不能重跑业务操作。
宿主生命周期钩子由宿主集成切片接入。

## 过大输出的自动有界缓存（6b/16）

提供可信存储时，普通文件、搜索和批处理输出超出序列化内联预算后，保留有界开头并返回
reference 与 referenceRoot（原始操作的规范根目录）。cwd 改变后分页仍须传入该原始根目录。
显示 complete 为 false；原始状态、修改数量/副作用和扫描覆盖事实保持不变。小结果不创建缓存。
worker 仅捕获请求的范围或页，不会把查询静默扩大成整棵目录树。

引用页包含 source：原始非 items 执行事实，以及 root、itemEncoding: "tagged-json-v1"、
capturedItems（逻辑条目数量）和 captureComplete。原始 scanComplete/matchedTotal、版本、范围
及 continuation 语义保留其中。page.complete 仅表示存储记录已显示完毕，不证明扫描或捕获完整。
read_many 的一个逻辑条目是完整逐文件回执，包括行、版本、范围及错误；逐文件失败仍为结果值。

小条目编码为 `{ kind: "item", index, value }`；大条目编码为一串有界的
`{ kind: "item-json-chunk", index, chunk, byteOffset, text, complete }`。index 和 chunk 从零开始；
byteOffset 计算逻辑 JSON 序列化后的 UTF-8 字节。按 chunk 顺序连接 text，仅在最后一块的
complete=true 后 JSON.parse；须验证连续索引、偏移及结束标记。StorageReference.totalItems
计算物理记录数，source.capturedItems 计算重建后的逻辑条目数。分块发生在显示裁切前，因此
被检查行的 Unicode、控制字符与行尾内容均可恢复。

捕获预算小于 10 MiB 实际快照配额。若某个逻辑条目放不下，其全部块会回滚，仅存储此前完整
条目；source.captureComplete 为 false，storageError 报告 QUOTA_EXCEEDED。缩小查询以获取
缺失范围。捕获完整性独立于原始扫描完整性；引用页绝不会再次溢出为引用。

缓存失败附加有界的 `storageError: { code, message, effectState }`，其中 effectState 仅描述
缓存副作用，与业务 status/changed/effectState 分开。只读观察不能创建引用。缓存拒绝时保留
不完整的有界开头，并提示范围/十六进制恢复；已完成的修改不能重跑。发布前先验证引用元数据
能否放进头部预算，避免因预算过小而留下无法取得的快照。没有可信存储时保留旧传输契约，
由宿主在存储不可用时补充恢复指导。
