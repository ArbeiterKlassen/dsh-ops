# 原生内核工作区

English: [native-kernel.md](native-kernel.md).

`dsh-ops-worker` 仍然是唯一的可执行文件。每次调用都经过 DSH 的 subprocess 和权限沙箱，
重新核实权限，读取一次有大小上限的 JSON 请求，再输出一个 JSON 结果。拆分内核不会引入常驻进程。

| crate | 职责 | 内核依赖 |
| --- | --- | --- |
| `ops-protocol` | 请求、错误、作业记录、凭据路径和归属校验 | 无 |
| `ops-files` | 禁止跟随链接的句柄、读取、CAS 发布、元数据、树操作、目录同步 | protocol |
| `ops-search` | 基于受保护文件原语的 glob、grep 和替换编排 | protocol、files |
| `ops-results` | 有界的代际存储、结果分页和只读作业审计访问 | protocol、files |
| `ops-batch` | 计划、预写状态转移和保守恢复 | protocol、files、results |

根 crate 负责分派请求，仅为 batch/result 能力打开审计存储。作业归属校验与协议记录放在一起，
避免结果模块依赖批处理执行模块。Windows 和 Darwin 元数据 crate 仍是独立 FFI 边界；内核 crate
禁止 unsafe Rust。替换操作保留观察锁直到发布完成；批处理在产生文件系统副作用前持久化 unknown
状态。只读文件调用不会创建审计存储。

使用 `cargo test --workspace --locked --manifest-path native/Cargo.toml`，确保迁入各 crate 的
测试全部执行。`npm run build:ptc` 的 worker 输出路径保持不变。发布包包含 `native/crates/`
及两个元数据适配器，支持安装后的源码构建。基准测试预检检查整个工作区的构建输入，并排除 Cargo
的 target 目录。

## 单次请求协议

新的宿主桥接发送 `{ version: 1, requestId, component, budget, request }`。`request` 保留严格的
能力参数和宿主权限字段；`component` 为 `file` 或 `ptc`，不会授予权限。桥接生成新的 UUID，
填入真实会话、根路径和策略，并在启动进程前再次核实权限。成功结果 JSON 保持不变。

`budget.timeoutMs` 范围为 1..2147483647 毫秒，沿用现有 300000 毫秒默认值及宿主取消机制。
进程内的看门狗也会约束直接调用；超时退出码为 124，桥接将副作用报告为 unknown。
`budget.maxBytes` 范围为 1024..131072，默认 131072，计算序列化 JSON 与末尾换行的总字节数。
下限保证结构化错误有足够空间。读取输出超限返回 `OUTPUT_LIMIT` 且无副作用；修改回执丢失则
报告 unknown，除非已有错误携带更精确的副作用状态。不会自动重试。

完整请求仍以 2 MiB 为上限。为兼容 0.3.x 基准对比，显式保留旧版无版本请求，采用相同权限检查和
有界默认传输预算。只要出现任一信封字段，就严格按 v1 解析；缺字段、未知字段、非法 ID、
不支持的组件或版本、无法使用的预算，均在文件系统副作用前被拒绝。请求 ID 不改变结果哈希。
扫描、存储和引用预算由后续切片实现。
