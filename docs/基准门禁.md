# 基准门禁

English: [Scripted acceptance benchmarks](benchmark-gates.md).

`node bench/cli.mjs gates` 通过固定 DSH `0.2.0-rc.2` 的真实 AgentLoop、Session、工具派发与权限服务运行 BM-01–05。确定性供应商脚本选择调用，不使用付费模型或网络模型请求。测量对象是工具行为、文本及交互轮数，不代表模型质量或计费 token。本套件按需运行，不进入默认功能门禁。

```console
npm ci --ignore-scripts
npm run build
npm run build:ptc
node bench/gates/prepare-baseline.mjs baseline-031
cargo build --release --locked --manifest-path baseline-031/native/Cargo.toml
node bench/cli.mjs gates --baseline-source baseline-031 --baseline-worker baseline-031/native/target/release/dsh-ops-worker --output benchmark-gates.json
```

Windows 的基线 worker 路径须加 `.exe`。每次运行使用新的输出文件名，JSON 证据与 `.md` 摘要都拒绝覆盖。工具保留独占创建的临时夹具目录以便检查。`--task BM-02` 仅选择一个门禁，其成功不能代表五项全部通过。所选项失败或不可用时退出 1；参数错误或缺少构建输入时退出 2。

手动工作流 `Opt-in OPS acceptance benchmarks` 在 Windows x64、Linux x64 和 Apple Silicon 上运行同一命令，独立构建基线，并在门禁失败时仍上传两份产物。默认 CI 要求不变，无需模型凭据。

## 固定工作负载与比较方式

| 门禁 | 证据与条件 |
| --- | --- |
| BM-01 | 三个包含 70/80/90 行的 TypeScript 文件，各取前 50 行，来自议题正文的具体示例。一个 `read_many` 分别对比 OPS 0.3.1 与固定宿主的官方 `read`。先断言规范数据及实际输出都完整保留请求行，再测字节。分别报告基线串行三轮与并行一轮控制组，以及包含最后回答的供应商总请求数。两项 40% 比较各自明确保留。 |
| BM-02 | 单文件五处独立编辑，一次提交成功，然后制造两种外部修改导致的旧 CAS 冲突。验证准确字节、全部冲突被拒绝，以及不复读完整文件。 |
| BM-03 | 测量第一次真实供应商请求中的完整默认 Native Schema。Windows 包含真实 jobs 服务下发布的 Bash 契约，缺失时阻塞。使用固定 `js-tiktoken@1.0.21`、`cl100k_base` 对紧凑 `name/description/parameters` JSON 计数，启动消息总量另列。完整 ≤400 目标仍待解决，不暗中替换为更窄口径。 |
| BM-04 | 真实单页 Helvetica/Flate PDF。初始无 PDF Schema；第一请求发现后，第二请求必须显示 `pdf_read`，兄弟作用域仍不可见，并验证提取文本。尚未集成 PDF 时明确阻塞。 |
| BM-05 | 工作区外凭据围栏读取与越界写入都须返回 rejected、保持文件不变，并且不披露被拒父路径或秘密正文。普通 OS 可读的工作区外文件作为允许读取的独立控制组：固定宿主不提供全面的工作区读取围栏。 |

BM-01 始终保留偏移 13/31/51、每文件 8 行的案例，以及 1 行、32 行、约 600 字符长行和转义 Unicode/JSON 敏感性案例。夹具定义冻结，证据记录文件散列与夹具源文件散列，不自动挑选有利案例。

运行功能门禁中的来源校验测试或准备基准基线前，检出必须包含固定的 0.3.1 Git 历史。浅克隆请先运行 `git fetch --unshallow`。CI 完整门禁任务与手动基准工作流获取完整历史；缺少基线对象属于失败，不会跳过。

0.3.1 基线固定为 `4b51b6333213c376c8b7c173c12f35b408fdec2d`。准备脚本直接还原 Git blob，避免 checkout 换行转换；运行前逐一校验 `lib/` 与 `native/`，并记录 worker 版本及 SHA-256，不宣称二进制可重现构建认证。官方比较组独立使用已安装的固定版本宿主读取器。测试专用 `@deepseek-ai/dsh-jobs-local@0.2.0-rc.2` 发布于 2026-09-29，添加时已超过七天，用于完整计量 Bash Schema。

## 保留的结果与限制

早期只运行 worker/渲染器的 3×8 探针得到基线 2,256、候选 1,949 字节（下降 13.608%），`modelRounds: null`、`hostAuthorityExercised: false`，只作为有限的历史证据保留。

随后真实 AgentLoop 的主案例得到 OPS 0.3.1 为 8,883、官方读取器 5,457、候选 6,239 字节。使用同一规范结果重放紧凑渲染器后为 5,348 字节，相比 0.3.1 下降 39.795%，仍未达到 40%；最终集成后的完整宿主重跑仍然必需。

主案例仅原始行内容就有 4,320 UTF-8 字节，而比官方 5,457 字节少 40% 要求不超过 3,274.2 字节，因此即使不计路径、版本与覆盖信息，也无法在不省略或压缩原文的前提下通过。报告列出这一数值下界及示例绝对路径/范围标签成本；共享父目录可缩短后者。长行同样使通用百分比节省不成立。路径、宿主契约和渲染版本会影响字节，所以保留全部准确输入与回执。

Windows 完整 Bash schema 测量需显式夹具：在独立临时 `DSH_HOME` 运行 `node bin/dsh-ops.mjs bash-runtime install`，将 `DSH_OPS_TEST_BASH` 指向经验证的绝对可执行路径。基准记录该选择，不修改 schema 选项；全新目录未安装 Bash 时，BM-03 明确阻塞，不以文件工具的较小计数冒充通过。手动工作流会显式获取该固定夹具。

## 审查后的完整重跑

干净候选 `2865936` 包含可逆源文本转义和独立完整性断言。本地保留 `040-benchmark-reviewed-complete.json`，SHA-256 为 `380ac6fbd392dd0f7805c03c66aa6ba9d88f88bcf4eb5a60ba01868f152488bb`。BM-01 仍为 5348/8883/5457 字节；BM-03 实际供应商顺序仍为 660 tokens/3219 字节。BM-02、BM-04、BM-05 通过，五项完整验收仍为 false。

修复后的 Unicode 敏感性为候选 2616、OPS 0.3.1 为 4185、官方 2469 字节：相对 OPS 减少 37.491%，相对官方增加 5.954%（即减少 −5.954%）。上方旧 40.358% 属于不可逆转义，只保留为历史记录。完整启动消息 JSON 另为 788 tokens/3293 字节，不作为工具 schema 门槛。最终版本候选仍需用重新构建的 worker 重跑。

## 审查后的完整性断言

BM-03 在评估 token 分数前，要求完整且精确的常驻文件能力目录与发现入口（Windows 还要求完整 Bash 契约）。缺失、重复或意外工具均会阻塞并指出原因。BM-05 同时要求普通外部读取对照成功且正文完全一致，并验证拒绝探测的 `CREDENTIAL_DENIED` / `POLICY_DENIED` 及 `effectState: none`。Native 行检查使用独立解码器验证反斜杠与控制字符，不再复制渲染器逻辑。这些断言不改变工作负载、默认值、预算或阈值；上方快照仍是所列提交的历史证据，不会被改判为通过。
