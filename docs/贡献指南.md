## 开发环境

| 组件 | 要求 |
| --- | --- |
| Node.js | `^22.19` 或 `>=24`（见 `package.json#engines`） |
| Rust | 仅在改 `native/` 或 `vendor/fastctx/` 时需要；工具链 `1.97.1` |
| 目标宿主 | DSH `0.2.0-rc.2` |

```console
npm install
npm run verify
```

## 验证门禁

`npm run verify` 是唯一门禁入口，等于两道检查：

1. `node scripts/validate-manifest.mjs` —— 用固定版本的 `@dsh-std/manifest` 解析并投影 `dsh-plugin.json`，再核对「仓库关于自己的事实」（版本/许可证、入口、工具命名空间、`package.json#files` 白名单等）。
2. `node test/run.mjs` —— 每个 `test/*.test.mjs` 独立进程、独立临时 `DSH_HOME`。

**新增行为必须同时补断言**；与挂载相关的改动必须能在 `test/mount.test.mjs` 里被证伪。提 PR 前请确保本地 `npm run verify` 全绿。

## 代码与文档约定

- **语言**：代码、注释、CLI 输出、提交信息一律英文；对外文档中英双语；面向维护者的说明用中文。
- **文档命名**：`docs/` 下同一文档中英各一份，例如 `docs/usage.md` 与 `docs/使用指南.md`。
- **工具名**：一律经 `lib/policy.js` 的 `publicToolName()` 生成，不要手写 `ops_` 前缀。
- **配置校验**：放在 `lib/config.js`，未知键必须报错并点名；`cordis.patch.yml` 里的默认值必须与代码默认值一致。
- **解析与探测**：同步放在 `apply` 里；`required: true` 必须在加载期拒绝激活。

## 提交与 PR

- 小步提交，提交信息用英文祈使句，例如 `fix: report undeclared background arguments as argument errors (#14)`。
- 使用真实作者身份；不空提交刷数、不伪造署名、不重写已推送历史。
- 较大的改动先开 issue 讨论；PR 描述写清动机、影响面与验证方式。
- 本仓库 Actions 默认关闭；CI 由维护者按需放行。

## 不可触碰的边界

- 宿主半边**不得在加载期 import `@deepseek-ai/*` 值**；需要宿主服务时用 `ctx.inject([...])` / `ctx.get()`。
- **绝不改写共享工具注册表**：只通过本插件自己的 `ctx.tools.register` 发布 `ops_*` 工具。
- 提示词段的取值必须用 `ctx.get('tools')`，不能用 `ctx.tools`。
- `vendor/fastctx/` 的改动只限「删」；确需改 `src/` 时按 Apache-2.0 §4(b) 在文件头加声明并登记到 `vendor/fastctx/FORK.md`。
- 不得为降低 schema / 提示词字节数删掉工具契约（参数语义、默认值、路径基准、分页完整性、权限边界等）。

## 许可证与署名

本插件除 `vendor/fastctx/` 外为 MIT；`vendor/fastctx/` 为 Apache-2.0。`NOTICE` 与两份 README 中上游要求逐字转载的致谢**必须原样保留**，不要「顺手润色」。

原生组件的编译与验收细节见 [native-ptc.md](native-ptc.md) 与 [manual-validation.md](manual-validation.md)。
